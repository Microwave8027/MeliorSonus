# MeliorSonus Audio Processing Audit: Dead Code, Dummied Implementations & Optimization Roadmap

This document provides a comprehensive audit of the MeliorSonus Rust audio processing pipeline (`shared/src/commonMain/rust/audio_processing/`). It catalogs dead code, orphaned functions, dummied implementations, and unnecessary CPU workloads—including an in-depth review of the **Spectral Centroid** implementation.

---

## 1. Deep Dive: Spectral Centroid (`spectral_centroid.rs`)

### 1.1 What It Is & What It Computes
* **Definition:** In [`spectral_centroid.rs`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/processing/functions/spectral/spectral_centroid.rs#L7-L23), spectral centroid is the center of mass of the frequency spectrum:
  $$\text{Centroid} = \frac{\sum_{k} f_k \cdot |X(k)|}{\sum_{k} |X(k)|}$$
* **Acoustic Meaning:** It measures perceived **timbral brightness or sharpness** (higher = brighter/harsher; lower = darker/muffled).

### 1.2 The Execution Trace
1. **Per-Hop FFT:** In [`HybridFeatureExtractor::dsp_callback`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/processing/feature_extraction/current_feature_extractor/hybrid_extractor.rs#L600-L603), on every audio frame (regardless of mode):
   ```rust
   self.real_fft.compute_magnitude_spectrum(&filtered_frame);
   let spectral_centroid = compute_spectral_centroid(&self.real_fft.magnitude, cfg.sample_rate as f32);
   ```
2. **Accumulation:** Passed through [`StreamingNoteSegmenter`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/neural/note_segmenter.rs#L741) into [`RecordNote::accumulate_frame`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/instruments/notes.rs#L483) (`self.sum_spectral_centroid += centroid`).
3. **Averaging on Release:** In [`notes.rs`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/instruments/notes.rs#L539-L543):
   ```rust
   let avg_centroid = if self.active_frames > 0 {
       self.sum_spectral_centroid / self.active_frames as f32
   } else {
       800.0 // Hardcoded fallback
   };
   ```
4. **Storage:** Stored in [`EndNote.spectral_centroid`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/instruments/notes.rs#L173).

### 1.3 Why It Is Currently Useless & Ineffective
* **No "Harsh" or "Mellow" Classification:** There is no classification, thresholding, or qualitative enum (like `Timbre::Harsh` or `Timbre::Mellow`). It is merely an uninterpreted raw floating-point frequency in Hertz (e.g. `1420.5`).
* **Zero Algorithmic Consumption:** It is **not** used by pitch detection, note segmentation, onset/offset detection, velocity calculation, or articulation classification.
* **Zero UI Consumption:** Neither Android nor iOS/Compose Kotlin code consumes, formats, or displays `spectral_centroid`.
* **Wasted Audio-Thread FFT:** In ByteDance mode (`PitchDetectorMode::Crnn`), executing `self.real_fft.compute_magnitude_spectrum` on the native audio thread every hop serves only to compute this unused number and `hfc_onset_ts` (which ByteDance ignores).
* **Mel Spectrogram Redundancy:** If timbral brightness is ever needed in the future for ByteDance, it can be computed directly from the **229 Slaney Mel bins** generated by [`SlaneyMelFrontend`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/processing/functions/spectral/mel_spectrogram.rs#L27) with zero additional FFT overhead.

## 4. Real-Time Audio Loop Bottlenecks (`dsp_callback`)

### 4.1 Unconditional FFT Execution in Pure CRNN Mode
* **File:** [`HybridFeatureExtractor::dsp_callback`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/processing/feature_extraction/current_feature_extractor/hybrid_extractor.rs#L600-L609)
* **Problem:** Every incoming hop (e.g. every ~10.6 ms at 48 kHz), the audio thread executes:
  1. `self.real_fft.compute_magnitude_spectrum(&filtered_frame)` (1024-point forward FFT)
  2. `compute_spectral_centroid(...)`
  3. `self.hfc_onset_detector.process_frame(...)`
* **Analysis:**
  * When `pitch_detector_mode == PitchDetectorMode::Crnn`, `hfc_onset_ts` is **not passed** to `process_crnn_path` or `process_bytedance_crnn_frame`.
  * ByteDance CRNN predicts note onsets via its own dedicated 88-note neural head (`output.onsets`).
  * `spectral_centroid` is only stored as an unread float on `EndNote`.
* **Optimization:** Gate `self.real_fft` and `hfc_onset_detector` so they **only execute when monophonic MPM mode is active**:
  ```rust
  let (spectral_centroid, hfc_onset_ts) = if self.pitch_detector_mode != PitchDetectorMode::Crnn {
      self.real_fft.compute_magnitude_spectrum(&filtered_frame);
      let centroid = compute_spectral_centroid(&self.real_fft.magnitude, cfg.sample_rate as f32);
      let onset = self.hfc_onset_detector.process_frame(self.real_fft.magnitude.as_slice(), dbfs, timestamp);
      (centroid, onset)
  } else {
      (0.0, None)
  };
  ```

## 5. Architectural Redundancy: Dual Neural Transcribers

[`HybridFeatureExtractor`](file:///C:/Users/micro/StudioProjects/MeliorSonus/shared/src/commonMain/rust/audio_processing/processing/feature_extraction/current_feature_extractor/hybrid_extractor.rs#L40-L66) currently maintains two distinct neural inference paths in parallel:

```
HybridFeatureExtractor
├── Path A: Spotify Basic Pitch (Legacy)
│   ├── resampler: Option<AudioResampler> (22.05 kHz)
│   └── transcriber: Option<Box<dyn NeuralTranscriber>>
└── Path B: ByteDance CRNN (Modern)
    ├── resampler_16k: Option<AudioResampler> (16.0 kHz)
    ├── bytedance_crnn: Option<ByteDanceCrnnModel>
    ├── slaney_mel: SlaneyMelFrontend (229 Log-Mel bins)
    ├── pcm_16k_fifo: [f32; 4096]
    └── mel_context_tensor: [f32; 7328]
```

* **Observation:** The ByteDance model outputs all 7 required heads (note onsets, offsets, frames, velocity, pedal onset, pedal offset, pedal frame), rendering Spotify Basic Pitch largely redundant.
* **Recommendation:** If the transition to ByteDance is complete, deprecating the Basic Pitch path (`transcriber`, `resampler`, `basic_pitch.rs`) will eliminate ~1,500 lines of complex runtime glue and simplify `StreamingNoteSegmenter`.
